# desktop-distribution Specification

## Purpose
定义新用户如何从安装包启动 Pizza、检测本机运行时并完成首次配置，以及 macOS 安装包应包含哪些版本与许可信息。

## Requirements

### Requirement: 首次启动运行时检测

本要求为强制要求（MUST）。

首次启动时，应用必须在 30 秒内检测本机已安装的运行时，并区分可接入、未安装和需要登录。未检测到运行时也必须允许用户进入应用并查看安装指引，不得阻断启动。

#### Scenario: 检测到可用运行时

- **WHEN** 用户首次启动且本机已安装 Claude Code
- **THEN** 引导页列出 Claude Code 为可接入
- **AND** 用户可以直接进入连接测试

#### Scenario: 没有可用运行时

- **WHEN** 用户首次启动且没有检测到任何运行时
- **THEN** 应用仍进入首页并显示安装指引
- **AND** 新建会话时提示先接入运行时

### Requirement: 首次配置流程

本要求为强制要求（MUST）。

引导流程必须覆盖选择或填写运行时、测试连接、注册运行时、创建第一个智能体和进入首个会话。除安装运行时本身外，用户不得被要求使用命令行。

#### Scenario: 完成首次配置

- **WHEN** 用户选择可接入运行时并通过连接测试
- **THEN** 应用注册运行时并预填通用助手智能体
- **AND** 用户可以进入首个会话

#### Scenario: 测试失败

- **WHEN** 运行时连接测试失败
- **THEN** 引导页显示失败步骤和修复建议
- **AND** 用户可以返回修改配置或稍后继续

### Requirement: 不打包用户运行时

本要求为强制要求（MUST）。

安装包不得捆绑或代替用户安装模型运行时。运行时由用户自行安装并登录，Pizza 只负责检测、连接和诊断。

#### Scenario: 查看安装包内容

- **WHEN** 用户检查安装包内容
- **THEN** 不应发现 Claude Code、Codex、Pi 等运行时的完整安装副本
- **AND** 关于页说明运行时需单独安装

### Requirement: macOS 安装包

本要求为强制要求（MUST）。

构建必须生成可在 macOS 13+ 启动的安装包，包含应用图标、版本、构建号和许可信息。安装后应用可以创建数据目录并打开主窗口。

#### Scenario: 安装并启动

- **WHEN** 用户安装构建产物并启动应用
- **THEN** 主窗口打开并创建本地数据目录
- **AND** 关于页版本与构建产物一致

### Requirement: 版本与许可信息

本要求为强制要求（MUST）。

安装包和关于页必须展示版本号、构建号、开源协议和第三方依赖归属。构建流程必须阻止版本号缺失或与包元数据不一致的产物发布。

#### Scenario: 版本号不一致

- **WHEN** 构建配置中的版本与包元数据不一致
- **THEN** 构建失败并指出不一致字段
- **AND** 不生成安装包

### Requirement: 数据目录初始化

本要求为强制要求（MUST）。

首次启动必须初始化 `~/.pizza` 数据目录、数据库和必要子目录。初始化失败时必须显示路径和修复建议，不创建半初始化状态。

#### Scenario: 初始化失败

- **WHEN** 数据目录无法创建或数据库初始化失败
- **THEN** 应用显示错误页和具体路径
- **AND** 不进入正常首页
