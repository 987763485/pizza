# tool-approvals Specification

## Purpose
定义智能体工具调用在需要用户授权时如何请求、展示、决定和审计，确保危险操作不会在用户不知情的情况下执行。

## Requirements

### Requirement: 统一审批请求

本要求为强制要求（MUST）。

ACP 权限请求和 CLI 审批钩子必须统一进入同一个审批服务，并向用户展示工具名称、参数摘要、风险等级、发起智能体和所属会话。不同运行时的审批不得各自实现一套 UI。

#### Scenario: ACP 请求写文件

- **WHEN** ACP 运行时请求在工作区外写入文件
- **THEN** 应用显示包含工具、路径和风险等级的审批对话框
- **AND** 运行进入等待审批状态

#### Scenario: CLI 请求执行命令

- **WHEN** CLI 适配器报告需要审批的命令
- **THEN** 应用使用同一审批对话框展示命令和参数
- **AND** 不自动执行命令

### Requirement: 审批决定

本要求为强制要求（MUST）。

审批必须支持允许一次、总是允许和拒绝。允许一次只对当前请求生效；总是允许只对同一智能体、工具和策略范围生效；拒绝必须向运行返回明确结果。

#### Scenario: 允许一次

- **WHEN** 用户选择允许一次
- **THEN** 当前工具调用继续执行
- **AND** 下一次同类调用仍会请求审批

#### Scenario: 拒绝执行

- **WHEN** 用户选择拒绝
- **THEN** 运行收到拒绝结果并显示可见错误
- **AND** 工具不被执行

### Requirement: 危险操作默认询问

本要求为强制要求（MUST）。

删除、覆盖、执行任意命令、访问工作区外路径和网络写操作必须默认每次询问。用户可以把某个工具设置为总是允许或禁止，但危险操作不得默认放行。

#### Scenario: 默认策略

- **WHEN** 一个新智能体第一次请求危险工具
- **THEN** 应用请求用户审批
- **AND** 不沿用未明确配置的全局放行

### Requirement: 审批策略

本要求为强制要求（MUST）。

用户必须能够为工具配置「总是允许」「每次询问」和「禁止」。策略按智能体和 MCP 工具范围生效，冲突时以更严格的策略为准。

#### Scenario: 禁止策略

- **WHEN** 用户把一个工具设置为禁止
- **THEN** 该工具调用直接返回拒绝
- **AND** 不弹出审批对话框

### Requirement: 超时与并发

本要求为强制要求（MUST）。

审批请求必须有超时；超时后按拒绝处理并向运行返回明确原因。多个审批同时到达时必须排队展示，不得丢失或覆盖尚未处理的请求。

#### Scenario: 审批超时

- **WHEN** 用户在超时时间内没有作出决定
- **THEN** 该请求按拒绝处理
- **AND** 运行收到超时原因

#### Scenario: 多个审批排队

- **WHEN** 两个运行同时请求审批
- **THEN** 用户依次看到两个请求
- **AND** 每个决定只作用于对应运行

### Requirement: 审批审计

本要求为强制要求（MUST）。

每次审批必须记录运行、智能体、工具、参数摘要、风险等级、决定、决定时间和策略来源。审计不得记录密钥或完整敏感参数。

#### Scenario: 查看审批记录

- **WHEN** 用户查看一次运行的审计记录
- **THEN** 可以看到审批决定和策略来源
- **AND** 敏感参数以摘要或掩码显示
