# workspace-artifacts Specification

## Purpose
定义会话产出物如何从工作区被发现、浏览、预览和打开，让用户能直接确认智能体实际写入的文件，而不是只看到聊天中的文本。

## Requirements

### Requirement: 产出物发现

本要求为强制要求（MUST）。

系统必须把智能体运行期间在工作区新增或修改的文件，以及写入 `.pizza/artifacts/` 的明确产出物，识别为本会话的产出物。新产出物必须在运行过程中或运行结束后出现在右侧面板，不得要求用户手动刷新整个应用。

#### Scenario: 智能体写入文件

- **WHEN** 智能体在工作区中新增一个文件并完成运行
- **THEN** 该文件出现在当前会话的产出物文件树中
- **AND** 文件带有新增状态标记

#### Scenario: 修改已有文件

- **WHEN** 智能体修改工作区中已有文件
- **THEN** 该文件在产出物中显示修改状态
- **AND** 用户可以看到文件路径和所属运行

### Requirement: 文件树与状态筛选

本要求为强制要求（MUST）。

产出物面板必须按目录结构展示文件夹和文件，支持展开、收起和按新增、修改、信息状态筛选。文件夹展开状态必须按会话保存。

#### Scenario: 展开文件夹

- **WHEN** 用户展开一个产出物文件夹后切换到其他会话再返回
- **THEN** 该文件夹保持展开状态
- **AND** 文件树显示最新文件列表

#### Scenario: 筛选修改文件

- **WHEN** 用户选择「修改」筛选条件
- **THEN** 文件树只显示具有修改状态的文件
- **AND** 清除筛选后恢复完整文件树

### Requirement: 产出物预览

本要求为强制要求（MUST）。

用户必须能够预览 Markdown、代码和图片产出物。Markdown 必须按渲染结果展示并可切换原文，代码必须保留格式，图片必须可缩放查看；预览不得修改源文件。

#### Scenario: 预览 Markdown

- **WHEN** 用户选择一个 `.md` 产出物
- **THEN** 面板渲染 Markdown 内容
- **AND** 用户可以切换查看原始文本

#### Scenario: 不支持的预览类型

- **WHEN** 用户选择一个当前不支持预览的文件类型
- **THEN** 面板显示文件信息和下载或外部打开入口
- **AND** 不尝试用错误格式渲染文件

### Requirement: 用首选编辑器打开工作区

本要求为强制要求（MUST）。

会话头部必须提供编辑器选择器，支持访达、Cursor、VS Code、Zed、IntelliJ IDEA、终端和 Warp。选择后必须立即生效并在重启后保留；当前编辑器没有安装时，必须提供安装指引和复制路径。

#### Scenario: 选择 VS Code

- **WHEN** 用户从编辑器下拉选择 VS Code 并打开工作区
- **THEN** 系统用 VS Code 打开当前会话的工作区路径
- **AND** 下次打开时仍默认使用 VS Code

#### Scenario: 编辑器不可用

- **WHEN** 用户选择的编辑器命令不存在
- **THEN** 应用显示该编辑器的安装指引
- **AND** 提供可复制的当前工作区路径

### Requirement: 路径失效处理

本要求为强制要求（MUST）。

当产出物文件或工作区路径被外部移动、删除或失去权限时，预览和打开操作必须显示具体错误，不得展示过期内容或静默失败。

#### Scenario: 产出物已被删除

- **WHEN** 用户打开一个已被外部删除的产出物
- **THEN** 面板显示文件不存在的提示
- **AND** 提供从文件树移除该条目的操作

### Requirement: 不在产出物面板重复打开入口

本要求为强制要求（MUST）。

会话头部已经提供打开工作区的首选编辑器操作，产出物面板不得重复放置同一打开按钮，避免同一动作出现两个入口。

#### Scenario: 查看产出物面板

- **WHEN** 用户打开右侧产出物面板
- **THEN** 面板提供文件树、预览和文件级操作
- **AND** 不出现与头部重复的「打开工作区」按钮
