# Spec Delta

## Purpose

定义智能体请求用户介入时如何通知用户，并确保通知可定位、可关闭且不会在免打扰时打扰用户。

## ADDED Requirements

### Requirement: 用户提及通知

本要求为强制要求（MUST）。

团队会话中智能体精确提及用户时，系统必须产生应用内通知、会话标记和系统托盘提示。通知必须包含会话名称、发起智能体和问题摘要。

#### Scenario: 智能体请求拍板

- **WHEN** 智能体提及用户并暂停回合
- **THEN** 应用内通知显示会话、智能体和问题摘要
- **AND** 对应会话出现等待用户标记

### Requirement: 点击跳转

本要求为强制要求（MUST）。

用户点击应用内通知或系统通知时，应用必须聚焦窗口、打开对应会话并定位到发起通知的消息。目标会话已被删除时显示不可用提示。

#### Scenario: 点击通知跳转

- **WHEN** 用户点击一条待处理通知
- **THEN** 应用聚焦并打开对应会话
- **AND** 消息流定位到触发通知的消息

### Requirement: 免打扰

本要求为强制要求（MUST）。

用户必须能够关闭系统托盘通知或设置免打扰。免打扰开启时不得发送系统通知，但必须保留应用内通知和会话标记。

#### Scenario: 免打扰期间请求

- **WHEN** 免打扰开启且智能体提及用户
- **THEN** 不发送系统托盘通知
- **AND** 应用内仍显示待处理标记

### Requirement: 重复通知抑制

本要求为强制要求（MUST）。

同一会话中同一待处理请求不得重复发送系统通知；请求状态变化或出现新的用户提及时才生成新通知。

#### Scenario: 同一请求多次渲染

- **WHEN** 界面因状态刷新多次渲染同一个待处理请求
- **THEN** 系统只发送一次通知
- **AND** 会话标记保持为待处理

### Requirement: 通知权限与降级

本要求为强制要求（MUST）。

系统通知权限被拒绝或托盘不可用时，应用必须降级为应用内通知并说明原因，不得静默丢失提醒。

#### Scenario: 系统通知权限被拒绝

- **WHEN** 用户拒绝系统通知权限
- **THEN** 应用内通知仍正常显示
- **AND** 设置页说明系统通知不可用
