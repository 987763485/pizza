# Spec Delta

## Purpose

定义团队会话中如何呈现多参与者消息、回合边界、等待状态、对话轨迹和收敛产出物，让用户能够理解谁在做什么、为什么停住，以及最终结果是什么。

## ADDED Requirements

### Requirement: 多参与者消息身份

本要求为强制要求（MUST）。

团队会话必须为每条智能体消息显示头像、名称、指挥者或成员标签和运行状态。同一智能体连续消息可以合并头部，但不同参与者之间必须可快速辨认；五个智能体同时发言时不得混淆身份。

#### Scenario: 五名成员同时发言

- **WHEN** 一个团队回合中五名成员先后产生消息
- **THEN** 每条消息都能看到对应参与者的头像和名称
- **AND** 指挥者与普通成员具有不同的角色标签

#### Scenario: 连续消息合并头部

- **WHEN** 同一智能体连续发送两条消息且中间没有其他参与者
- **THEN** 第二条消息可以合并头部显示
- **AND** 消息内容和状态仍分别可见

### Requirement: 回合分隔

本要求为强制要求（MUST）。

团队会话必须在回合开始时显示「第 N 轮」，在成员处理时显示当前参与者，在等待用户时显示「等待你回复」。回合分隔必须弱化显示，不得抢占消息内容的主视觉。

#### Scenario: 新回合开始

- **WHEN** 用户发送一条团队消息并触发新回合
- **THEN** 消息流中插入第 N 轮分隔
- **AND** 分隔中显示即将处理的参与者或默认指挥者

#### Scenario: 等待用户

- **WHEN** 智能体精确提及用户并暂停回合
- **THEN** 消息流显示醒目的等待用户状态
- **AND** 输入框提示当前回合正在等待用户回复

### Requirement: 运行状态真实呈现

本要求为强制要求（MUST）。

每条运行必须显示排队、启动中、运行中、等待审批、完成、失败、已停止或超时状态。界面不得用「正在输入」掩盖失败、等待审批或等待用户。

#### Scenario: 成员运行失败

- **WHEN** 一名成员运行以错误结束
- **THEN** 该消息显示失败状态和错误摘要
- **AND** 不使用运行中动画掩盖失败

#### Scenario: 等待用户

- **WHEN** 团队回合因提及用户而暂停
- **THEN** 相关运行显示等待用户
- **AND** 用户可以继续输入回复

### Requirement: 用户插话状态

本要求为强制要求（MUST）。

用户在团队运行中发送的消息必须显示其投递状态：已排队、已插话或已发送。用户直接提及某成员时，状态必须说明该消息只送达该成员；未提及时说明送达指挥者。

#### Scenario: 插话只送达成员

- **WHEN** 用户在运行中提及成员 A 并发送消息
- **THEN** 消息显示送达成员 A
- **AND** 其他成员不收到该消息

#### Scenario: 排队状态更新

- **WHEN** 一条排队消息在运行结束后被送达
- **THEN** 其状态从已排队变为已发送
- **AND** 消息流中保留状态变化记录

### Requirement: 对话轨迹

本要求为强制要求（MUST）。

团队会话必须提供「对话轨迹」页签，展示本回合的参与者、关键调度、辩论、插话、停止和收敛事件。轨迹必须与会话同步更新；切换页签或切换会话后不丢失状态。

#### Scenario: 查看调度轨迹

- **WHEN** 用户切换到对话轨迹页签
- **THEN** 可以看到本回合的参与者及其当前状态
- **AND** 可以看到指挥者分派成员的关键事件

#### Scenario: 切换会话后返回

- **WHEN** 用户从团队会话 A 切换到会话 B 再返回 A
- **THEN** 对话轨迹仍显示 A 当前回合的最新状态
- **AND** 不显示 B 的轨迹内容

### Requirement: 收敛产出物展示

本要求为强制要求（MUST）。

团队收敛后，指挥者的 Markdown 总结必须作为产出物出现在右侧面板，并包含结论、关键依据、分歧与未决问题、建议下一步。产出物必须可预览，且与会话内消息内容一致。

#### Scenario: 收敛后查看产出物

- **WHEN** 指挥者完成收敛并保存总结
- **THEN** 右侧产出物面板出现对应 Markdown 文件
- **AND** 打开预览可以看到与消息中一致的结论内容

#### Scenario: 产出物写入失败

- **WHEN** 收敛总结因工作区权限或路径错误无法写入
- **THEN** 会话内仍保留完整总结文本
- **AND** 界面提示写入路径和失败原因
