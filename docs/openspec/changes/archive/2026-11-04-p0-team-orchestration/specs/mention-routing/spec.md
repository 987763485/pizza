# Spec Delta

## Purpose

定义团队会话中 `@` 提及的解析与路由规则，确保跨智能体分派可追踪、可去重、可打断，并且不会因重名或未知目标产生错误调度。

## ADDED Requirements

### Requirement: 用户提及输入

本要求为强制要求（MUST）。

用户在团队会话输入 `@` 时必须看到分组选择器，至少包含指挥者、团队成员和我。选择后必须插入可识别的提及 chip，并保存目标标识、显示名称和位置。

#### Scenario: 选择团队成员

- **WHEN** 用户在输入框中输入 `@` 并从选择器选择一名成员
- **THEN** 输入框出现带该成员头像和名称的提及 chip
- **AND** 消息发送时保存该成员的稳定标识

#### Scenario: 选择我

- **WHEN** 用户从提及选择器选择「我」
- **THEN** 插入指向当前用户的提及
- **AND** 该提及不会触发任何智能体运行

### Requirement: 智能体精确提及语法

本要求为强制要求（MUST）。

智能体输出中的跨智能体分派必须使用精确提及语法 `[@名称](mention://agent/<id>)`。系统必须解析该语法并路由到对应成员；纯文本 `@名称` 不得触发智能体调度。

#### Scenario: 精确提及触发调度

- **WHEN** 指挥者输出 `[@架构师](mention://agent/agent-123)`
- **THEN** 编排器向 `agent-123` 创建一次运行
- **AND** 消息中保留可点击的提及 chip

#### Scenario: 纯文本提及不调度

- **WHEN** 智能体输出纯文本 `@架构师` 而没有精确提及链接
- **THEN** 文本保持原样显示
- **AND** 不创建新的智能体运行

### Requirement: 目标解析顺序

本要求为强制要求（MUST）。

提及目标必须按「本会话精确名称 → 本团队内名称 → 全局唯一名称」的顺序解析。重名且无法唯一确定时不得猜测，必须插入系统提示说明提及不明确。未知目标必须保留原文并显示「未找到该智能体」。

#### Scenario: 团队内重名

- **WHEN** 两个团队成员具有相同显示名称且没有稳定标识
- **THEN** 系统不调度任何成员
- **AND** 插入要求使用稳定标识的系统提示

#### Scenario: 未知目标

- **WHEN** 消息提及一个不在当前团队中的名称
- **THEN** 原文保持可见
- **AND** 消息旁显示未找到该智能体的提示

### Requirement: 用户消息路由

本要求为强制要求（MUST）。

用户消息未提及时必须默认路由给指挥者。用户直接提及一个或多个成员时，必须分别调度每个目标；同一条消息重复提及同一目标只调度一次，并向指挥者发送被动通知而不自动运行指挥者。

#### Scenario: 未提及时默认路由

- **WHEN** 用户在团队会话中发送一条没有提及的消息
- **THEN** 指挥者获得一次运行
- **AND** 其他成员不被调度

#### Scenario: 多个成员提及

- **WHEN** 用户在同一条消息中提及成员 A 和成员 B
- **THEN** A 和 B 各获得一次运行
- **AND** 同一条消息中重复提及 A 不会产生第二次运行

#### Scenario: 直接提及成员时抄送指挥者

- **WHEN** 用户直接提及成员 A
- **THEN** A 获得运行
- **AND** 指挥者收到一条被动通知但不自动运行

### Requirement: 智能体消息路由

本要求为强制要求（MUST）。

智能体提及团队成员时，必须把触发消息、调用者任务说明和共享上下文传给目标成员。智能体提及用户时必须暂停回合并进入 `waiting_user`。智能体未提及其他目标时，回复必须返回调用者；调用者是用户时结束本回合。

#### Scenario: 成员回复指挥者

- **WHEN** 成员完成一次由指挥者触发的运行且没有提及其他目标
- **THEN** 该回复返回指挥者
- **AND** 指挥者被再触发以评估下一步

#### Scenario: 智能体请求用户拍板

- **WHEN** 成员输出指向用户的精确提及
- **THEN** 会话进入等待用户状态
- **AND** 用户回复后恢复被暂停的回合

### Requirement: 禁止自我提及

本要求为强制要求（MUST）。

智能体不能通过提及自己触发新的运行。自引用必须被忽略，并记录一条可审计事件，不得导致循环调度。

#### Scenario: 智能体提及自己

- **WHEN** 智能体输出指向自身的精确提及
- **THEN** 编排器不创建新运行
- **AND** 审计中记录一次被忽略的自引用

### Requirement: 再触发规则

本要求为强制要求（MUST）。

成员回复后必须唤醒指挥者；如果成员显式提及其他目标，则按显式目标调度而不额外唤醒指挥者。指挥者自己的发言不得触发自己。再触发必须去重，避免同一消息重复入队。

#### Scenario: 成员回复后唤醒指挥者

- **WHEN** 成员完成回复且没有显式提及其他目标
- **THEN** 指挥者收到一次再触发
- **AND** 同一回复不会再次触发指挥者

#### Scenario: 成员显式提及其他成员

- **WHEN** 成员回复中精确提及其它成员
- **THEN** 只调度被提及的成员
- **AND** 不额外唤醒指挥者

### Requirement: 上下文组装

本要求为强制要求（MUST）。

每次团队运行必须注入系统约束、当前任务、角色配置、团队名单、最近会话上下文、能力清单和工作区信息。指挥者被唤醒时必须看到自上次发言以来的成员消息摘要和原文；上下文超出阈值时必须保留当前任务、未决问题和产出物路径。

#### Scenario: 指挥者看到成员进展

- **WHEN** 指挥者在成员并行回复后被再触发
- **THEN** 其上下文包含这些成员的回复摘要和关键原文
- **AND** 不包含已被压缩且与当前任务无关的旧消息

#### Scenario: 压缩后保留未决问题

- **WHEN** 会话上下文达到压缩阈值
- **THEN** 摘要保留当前任务、未决问题和产出物路径
- **AND** 原始消息仍可在会话历史中查看
