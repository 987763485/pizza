# Spec Delta

## Purpose

定义用户如何浏览、检索和维护历史会话，使大量会话仍然可发现、可恢复，并且归档或删除操作不会误伤其他工作区。

## ADDED Requirements

### Requirement: 按工作区归组的会话历史

本要求为强制要求（MUST）。

左侧栏必须按工作区展示会话，每个工作区直接列出其会话，不提供独立的全量会话列表或日期分组。没有工作区的会话必须归入默认工作区。

#### Scenario: 工作区下的会话

- **WHEN** 用户展开一个工作区
- **THEN** 只显示属于该工作区的会话
- **AND** 会话项显示标题、模式和运行状态

### Requirement: 会话搜索

本要求为强制要求（MUST）。

用户必须能够按会话标题、消息内容和智能体名称搜索会话。搜索结果必须高亮命中片段并能跳转到对应会话。

#### Scenario: 按消息内容搜索

- **WHEN** 用户输入一个出现在历史消息中的词
- **THEN** 搜索结果列出包含该词的会话
- **AND** 选择结果后打开对应会话并定位到命中消息

#### Scenario: 没有匹配结果

- **WHEN** 用户输入没有匹配的关键词
- **THEN** 界面显示空结果状态
- **AND** 用户可以清除搜索回到完整列表

### Requirement: 重命名会话

本要求为强制要求（MUST）。

用户必须能够重命名会话，修改在提交后立即反映到左侧栏和会话头部。空标题必须被拒绝。

#### Scenario: 重命名成功

- **WHEN** 用户输入非空新标题并确认
- **THEN** 会话标题立即更新
- **AND** 重启应用后仍保持新标题

### Requirement: 分叉会话

本要求为强制要求（MUST）。

用户必须能够从当前会话分叉出新会话。分叉必须复制分叉点之前的消息和配置，保留原会话不变，并自动切换到新会话。

#### Scenario: 分叉会话

- **WHEN** 用户对一条会话选择「分叉会话」
- **THEN** 系统创建包含分叉点之前消息的新会话
- **AND** 原会话保持不变且新会话获得新的标识

### Requirement: 归档与恢复

本要求为强制要求（MUST）。

用户必须能够归档会话，归档后会话从工作区列表移入已归档列表。用户必须能够在设置中的已归档会话里恢复或永久删除归档会话。

#### Scenario: 归档会话

- **WHEN** 用户归档一个会话
- **THEN** 该会话从当前工作区列表消失
- **AND** 已归档列表中出现该会话

#### Scenario: 恢复归档会话

- **WHEN** 用户从已归档列表恢复一个会话
- **THEN** 该会话重新出现在原工作区
- **AND** 消息内容保持完整

### Requirement: 永久删除会话

本要求为强制要求（MUST）。

永久删除会话前必须二次确认，并说明该操作不可恢复。删除一个会话不得删除同工作区的其他会话或共享文件。

#### Scenario: 删除确认

- **WHEN** 用户选择永久删除一个会话
- **THEN** 应用显示包含会话标题的二次确认
- **AND** 用户取消时会话保持不变

#### Scenario: 删除后隔离

- **WHEN** 用户确认永久删除一个会话
- **THEN** 该会话及其消息不再可查询
- **AND** 同工作区其他会话不受影响

### Requirement: 会话状态标记

本要求为强制要求（MUST）。

会话项必须显示未读、运行中、等待用户和失败等状态。状态不得只依赖颜色表达，必须同时提供文字或图形标记。

#### Scenario: 后台运行完成

- **WHEN** 一个后台会话的运行完成且用户尚未查看
- **THEN** 该会话显示未读标记
- **AND** 用户打开会话后标记清除
