## D-001 以会话与 `@` 为产品核心

- **背景**：参考实现以 Issue / 评论 / 看板为核心；Pizza 的构想是「从一次对话开始，@ 谁谁来解决问题」。
- **结论**：Pizza 不复用 Issue 领域模型，新增 `conversation`、`conversation_participant`、`message_mention`；复用底层的任务队列、运行时适配、Skill/MCP、实时通道与用量。
- **影响**：聊天不是附属功能，而是主界面；Issue/看板/收件箱不进入 Pizza 导航。
- **状态**：已确认。

## D-002 运行时接入：ACP 优先，CLI 兼容

- **背景**：目标运行时中，Hermes 原生支持 ACP；Claude Code、Codex、Pi、Oh My Pi、DeepSeek Harness 以 CLI / 自有 JSON-RPC 驱动。
- **结论**：Pizza 的运行时层定义为「统一适配层，ACP 优先，CLI 兼容」。UI 在运行时详情中标注协议类型，不向用户宣称所有运行时都走 ACP。
- **影响**：运行时注册向导需要同时支持 ACP 命令/地址与 CLI 命令；连接测试按协议分支展示步骤。
- **状态**：已确认（待逐个运行时验证命令与能力）。

## D-003 首页使用「参与者」下拉，不设模式切换

- **背景**：用户明确要求首页不要出现「智能体团队 / 单智能体」切换，改为下拉选择参与者。
- **结论**：首页输入卡只有一个「参与者」下拉，分组展示「智能体」与「智能体团队」；选中智能体即进入单智能体模式，选中团队即进入团队模式。当前项带勾选，菜单为深色浮层。
- **影响**：`SESS-13`；首页不再有独立模式控件；会话创建时由参与者类型决定 `mode`。
- **状态**：已确认（2026-11-03）。

## D-004 团队配置支持成员级覆盖与快照

- **背景**：参考实现的 Squad 只有 leader + 成员角色描述 + 团队指令，没有成员级 Prompt/Skill/MCP 覆盖与快照。
- **结论**：Pizza 的团队成员支持覆盖 Prompt（替换/追加）、增删 Skill、增删 MCP；团队配置可保存快照并恢复/复制。指挥者必须是成员。
- **影响**：新增 `team_member` 覆盖字段与 `team_snapshot`；配置解析优先级：团队覆盖 > 智能体自身 > 系统默认。
- **状态**：已确认。

## D-005 视觉方向：中性灰 + 黑白主操作 + 番茄品牌点缀

- **背景**：用户要求界面配色完全参考提供的桌面客户端截图；截图为中性灰背景、白色卡片、黑色主按钮、绿色在线状态。
- **结论**：主背景/卡片/边框使用中性灰阶；主操作与选中态使用黑白；番茄红只用于 Pizza Logo、少量品牌点缀；智能体身份使用角色色圆点/头像。
- **影响**：设计令牌、按钮、侧边栏、消息流、设置页全部按此体系；深色主题为近黑中性灰。
- **状态**：已确认（2026-11-03）。

## D-006 设置与管理页采用三段式布局（设置布局已由 D-022 取代）

- **背景**：用户提供了设置页与团队设置页截图。
- **结论**：设置页 = 64px 图标窄栏 + 252px 设置导航 + 内容；团队管理页 = 64px 图标窄栏 + 252px 团队导航 + 内容。内容使用卡片行、左标签右控件、轻分隔线。
- **影响**：`settings-shell` 与 `manage-shell` 共用 rail/nav 样式；管理页包含智能体、智能体团队、成员、Skills、MCP、运行时、统计。
- **状态**：已确认（2026-11-03）。

## D-007 技术基线：完整复用 + 本地化打包（待确认）

- **背景**：参考实现的 daemon、Provider 适配、任务队列、Skill/MCP 注入、用量与实时通道是最有价值的资产；但从零重写这些成本极高。
- **结论（推荐）**：保留 Go 服务端与 daemon，新增 Chat/Team 领域；将 Go 服务端与 PostgreSQL 打包进桌面应用，本地随机端口与本地令牌，实现本地优先。备选为 Electron + TypeScript + SQLite 的轻壳方案。
- **待确认**：安装包体积、PostgreSQL 生命周期、与上游同步成本。
- **状态**：**待用户拍板**。

## D-008 许可证与品牌归属（待确认）

- **背景**：参考实现采用自定义许可证（Apache-2.0 + 附加条件），限制移除其品牌/LOGO，并对托管服务与商业分发有额外要求。
- **结论**：代码阶段前必须三选一：取得品牌豁免/商业授权；保留归属并遵守条款；仅借鉴交互、独立实现。
- **影响**：决定 D-007 是否可行；任何方案都不得在未授权情况下移除归属信息。
- **状态**：**待用户确认**。

## D-009 指令来源模式：P0 只做模式一

- **背景**：需求中列出「自带初始 Prompt」与「指挥者动态下发」两种模式，并注明模式选择可放 P1。
- **结论**：P0 固定模式一；模式二与每个智能体的默认模式选择器放 P1。
- **状态**：待评审确认。

## D-010 群聊数据模型与实时授权

- **背景**：参考实现的 Chat 是 1:1 且仅创建者可见；多智能体 @ 只在 Issue 评论中存在。
- **结论**：新增房间/参与者/mention 模型；消息增加 `sender_type`、`sender_agent_id`、`round_no`、`status`；实时事件按会话参与者授权，不再沿用「仅创建者可见」。
- **影响**：需要扩展 Chat schema、mention 分发、房间级 WebSocket scope。
- **状态**：已确认（实现细节待架构评审）。

## D-011 右侧栏增加「对话轨迹」与每人 token 统计

- **背景**：用户要求把「本回合」参与者列表作为一个独立的「对话轨迹」页签，并在底部展示每位参与者的 token 消耗。
- **结论**：右侧栏页签为「产出物 / 轨迹 / 变更 / Git / 审计」；团队会话默认打开轨迹。轨迹页展示参与者状态、调度/辩论/插话/收敛事件，底部按参与者展示 token 占比与合计。
- **状态**：已确认（2026-11-03）。

- **状态**：已确认（2026-11-03）。

## D-013 账户、帮助菜单与图标窄栏精简

- **背景**：用户提供了账户菜单与帮助菜单截图，并要求删除管理页图标窄栏中多余的三个图标。

## D-014 多工作区并列

- **背景**：用户要求侧边栏支持多个工作区并列，并在每个工作区下显示最近任务。
- **结论**：左侧栏只保留工作区分组，会话直接挂在所属工作区下；置顶工作区进入顶部「置顶」分组；当前工作区高亮；没有工作区的会话归入默认工作区。删除独立的会话列表与日期分组。每个工作区提供「+ 新建任务」与「置顶/取消置顶/编辑/归档工作区」菜单。工作区首页显示名称、目录、活跃数与置顶按钮。

## D-017 会话右键菜单与分叉

- **背景**：用户要求每个会话提供右键菜单，并在菜单中加入「分叉会话」。
- **结论**：会话行右键与悬停「⋯」打开同一菜单，包含重命名、分叉会话、导出会话、归档、永久删除；不放置置顶、标记未读、在新标签页打开、复制链接。分叉复制当前会话到分叉点，创建标题追加「（分叉）」的新会话并立即切换；归档移出侧栏，永久删除二次确认。
- **状态**：已确认（2026-11-03）。

## D-018 标题栏提供左侧栏折叠与搜索

- **背景**：用户要求增加左侧折叠入口，并把搜索移到折叠按钮旁边。
- **结论**：标题栏左侧在交通灯之后依次放折叠左侧栏、搜索；右侧保留主题与右侧栏。侧栏品牌行不再放折叠按钮。折叠后侧栏收为 64px，仅保留品牌、新建、统计/设置/帮助与头像图标。
- **状态**：已确认（2026-11-03）。

## D-019 工作区切换使用系统文件夹选择器

- **背景**：用户要求点击当前工作区时打开电脑文件夹选择，而不是应用内列表。
- **结论**：输入区与首页的工作区入口都调用系统目录选择器；优先使用 File System Access API，失败时退回 `webkitdirectory`。选中目录后按名称复用已有工作区或创建新工作区，聊天中的当前会话随工作区迁移。
- **影响**：浏览器原型无法取得绝对路径，展示路径暂以 `~/Documents/<目录名>` 代替；桌面端接入后使用真实路径。
- **状态**：已确认（2026-11-03）。

## D-020 团队管理全部并入设置

- **背景**：用户要求把团队的所有功能融合到设置中，不再保留独立的管理外壳。
- **结论**：设置导航新增「团队」分组，包含智能体、智能体团队、成员、Skill、MCP、运行时与统计；列表、详情与编辑均在设置三段式外壳内渲染，原管理页路由自动映射到对应设置标签。设置导航只保留一级「智能体团队」，不再列出二级团队快捷入口。
- **影响**：管理页不再使用独立外壳；智能体/团队编辑、运行时接入以设置内容页形式呈现，返回路径回到设置列表。
- **状态**：已确认（2026-11-03）。

## D-021 配色调整为冷中性灰

- **背景**：用户要求参考桌面工作台的配色，降低暖色与高对比色块，突出内容。
- **结论**：背景为 `#FBFBFB`，侧栏/图标栏为 `#F3F3F4`，选中态为 `#EEEEF0`，边框为 `#ECECEE`；主操作为近黑 `#18181B`；番茄红仅用于品牌标记圆点与角色点缀；在线状态使用亮绿 `#22C55E`。品牌标记与首页图标改为白底黑字，减少大面积红色。
- **状态**：已确认（2026-11-03）。

## D-022 设置保留应用侧栏（已由 D-023 取代）

- **背景**：用户提供设置页参考布局，要求打开设置时左侧仍显示应用侧栏。
- **结论**：设置页改为「应用侧栏 + 设置导航 + 内容」三段式；不再使用 64px 图标窄栏。侧栏保留品牌、新建对话、工作区、会话与底部入口；进入设置后右侧面板隐藏。
- **状态**：已确认（2026-11-03）。

## D-023 设置改为独立视图

- **背景**：用户提供设置页参考图，要求点击设置后采用独立的品牌 + 导航 + 内容布局。
- **结论**：设置打开时隐藏应用侧栏；左侧 264px 合并品牌、设置导航与底部操作，底部提供「返回聊天」与主题切换；右侧为内容。不再保留应用侧栏或 64px 图标窄栏。
- **影响**：设置页与主工作区解耦；「返回聊天」回到当前会话，无活动会话时回首页。
- **状态**：已确认（2026-11-03）。

## 开放问题

1. **技术基线**：完整复用 + 本地打包，还是本地轻壳？——影响工期与许可证策略。
2. **许可证**：是否已取得品牌豁免/商业授权？——代码阶段的前置条件。
3. **「智能体的 mode」**：是否指「指令来源模式」？本文暂按此理解。
4. **运行中插话**：P0 是否只做排队？建议是；能力探测后再开放立即插话。
5. **团队快照**：完整副本还是引用？建议完整副本 + 版本号。
6. **产出物范围**：工作区新/改文件是否都算产出物？建议是，并在面板中标注来源运行。
7. **Git 面板**：P1 只读 + 基础提交，是否足够？
8. **目标用户**：个人开发者优先，还是 3–10 人团队优先？影响移动端与协作功能的优先级。
