# P0 团队编排设计摘要（候选）

- Change：`p0-team-orchestration`
- 日期：2026-11-04
- 状态：候选，待用户确认
- 依赖：已归档的 `p0-solo-vertical-slice`

## 1. 目标与边界

团队模式让用户把问题切成多块，交给一名指挥者和若干成员协作。本 change 交付团队 CRUD、头脑风暴模板、`@` 路由、会话级调度、插话/停止、循环与成本保护、结构化收敛和团队会话 UI。

不包含：团队快照、动态指令来源模式二、`@全体`、自然语言并行声明、Skill/MCP 实际注入、跨团队编排、安装包。

## 2. 关键技术方案

### 2.1 复用单智能体执行器（推荐）

从现有 `RunService` 中抽出 `AgentRunExecutor`，只负责一次运行的运行时生命周期、流式消息、事件落库、用量、产出物扫描和失败处理。单智能体 `RunService` 保留自己的会话级 FIFO 队列；团队新增 `TeamOrchestrator` 负责团队队列、并发与回合状态，并调用同一个执行器。

未选择：让 `TeamOrchestrator` 直接调用现有 `RunService.send`（会把单智能体队列和团队调度混在一起）；新增独立运行时进程（重复 IPC 和进程监督）。

### 2.2 数据模型

新增迁移：

- `team`：工作区、名称、描述、头像、指挥者、编排 Prompt、并行/串行策略、最大并发、最大轮次、最大跳数、token 预算、归档状态、最近使用时间。
- `team_member`：团队、智能体、排序、角色描述、Prompt 覆盖模式（继承/追加/替换）与内容、Skill/MCP 覆盖 JSON（只保存结构，本 change 不执行）。
- `message_mention`：消息、目标类型、目标智能体、显示名称、起止位置、原始语法、是否解析成功。
- `team_turn`：会话、回合序号、状态、触发消息、指挥者、开始/结束时间、收敛原因、跳数/轮次/token 统计、错误。
- `team_turn_event`：回合、序号、事件类型、参与者、运行、负载。
- `run` 增加 `team_turn_id` 可空外键；现有 `parent_run_id` 和 `trigger_message_id` 继续用于调用链。

回合状态：`dispatching → debating → waiting_user → converging → completed`，另有 `failed / cancelled / interrupted`。状态转换由主进程串行化。

### 2.3 提及解析与路由

新增共享纯函数模块 `mentions`：

- 智能体输出只认 `[@名称](mention://agent/<id>)`；纯文本 `@名称` 不调度。
- 用户消息支持提及 chip 序列化，也支持解析选择器插入的稳定标识。
- 解析顺序：会话精确名称 → 团队内名称 → 全局唯一名称；重名返回歧义并插入系统提示；未知目标保留原文。
- 同一目标去重；自引用忽略并写审计事件。
- 用户未提及时默认指挥者；直接提及成员时只调度成员，并向指挥者写被动通知；提及时用户则暂停回合进入 `waiting_user`。
- 成员完成且无显式提及时返回调用者；调用者是指挥者或用户时回到指挥者评估收敛；成员显式提及其他成员时只调度这些成员，不额外唤醒指挥者。

### 2.4 调度与并发

- 每个团队会话一个 `TeamOrchestrator`，串行处理状态转换，内存队列 + 数据库回合记录。
- 同一智能体同时最多一个运行；团队默认最大并发 3，可配置 1–10，并受全局并发设置约束。
- 并行：一次提及的多个成员同时启动；串行：按提及顺序执行，后一个成员上下文包含前一个成员结果。
- 用户插话进入会话队列；当前运行结束后按目标送达。P0 适配器均未声明追加输入，因此“立即插话”降级为排队并显示原因。
- 停止单个运行只取消目标运行；停止全部取消本回合所有运行并停止新调度。
- 崩溃恢复：启动时把未完成运行和回合标记为 `interrupted`，保留已完成结果，不自动重放；用户可重试。

### 2.5 上下文与保护

- `TeamContextBuilder` 组装系统协作协议、任务、调用者说明、成员有效配置、团队名单、最近消息、能力清单、工作区与产出物。
- 指挥者再触发时注入自上次发言以来的成员摘要与关键原文；串行成员能看到前一个成员结果。
- 上下文压缩使用确定性结构化摘要（保留任务、未决问题、决策、产出物路径，截断旧正文），不额外调用模型。
- 保护阈值：单回合跳数 12、辩论轮次团队配置（默认 5）、单运行超时 30 分钟、重复调用抑制 2 分钟、A→B→A 连续三次插入收敛提示；token 预算可选，默认 0（不限），达到 80% 提醒、100% 停止。
- 保护触发写 `team_turn_event` 并强制指挥者输出阶段性总结。

### 2.6 收敛与产出物

指挥者完成结构化总结后，主进程写入 `.pizza/artifacts/team-turn-<seq>.md`，索引到产出物面板；写入失败时保留会话内完整文本并显示路径/原因系统提示。总结必须包含结论、关键依据、分歧与未决问题、建议下一步。

### 2.7 UI

- 设置中的「智能体团队」从占位页升级为列表 + 整页编辑器：基本资料、指挥者/成员、成员覆盖、编排 Prompt、最终生效预览。
- 头脑风暴模板：用户选择运行时后，自动创建缺失的五名内置角色智能体并预填团队，可继续编辑。
- 首页参与者下拉增加「智能体团队」分组；选择团队创建团队会话。
- 团队会话复用三栏外壳：团队头部（指挥者、成员、头像堆叠）、回合分隔、多参与者消息头、等待用户卡片、单个/全部停止、插话状态、对话轨迹页签、收敛产出物。
- 输入框使用轻量 contentEditable 提及输入：`@` 打开分组选择器，插入不可编辑 chip，发送时序列化为稳定提及语法。
- 消息渲染把 `mention://agent/<id>` 与用户提及渲染为 chip；消息列表按发送者解析头像和角色标签。
- 对话轨迹读取 `team_turn_event`，不靠前端推断。

### 2.8 测试

- 提及解析表驱动测试覆盖用户/智能体、单个/多个、重名、未知、自引用、重复。
- 调度器单元测试使用假执行器和虚拟时钟，覆盖并发、串行、再触发、插话、停止、保护、恢复。
- 集成测试用五个假智能体完成分派、并行、辩论、收敛，并验证用户中途消息影响下一轮。
- Playwright 团队冒烟测试覆盖创建团队、发送任务、收敛、打开产出物。
- 真实运行时手工验收一次五成员头脑风暴和一次中途插话。

## 3. 需要用户确认的取舍

1. **token 预算默认值**：建议默认 0（不限），团队编辑页可设置 200k/500k/1M/自定义；达到阈值时提醒/停止。这样不会在首次体验时因默认预算过小打断辩论。
2. **模板自动创建智能体**：建议从头脑风暴模板创建时，若五个角色不存在，则在用户选择的运行时上自动创建，减少首次使用步骤。
3. **运行中插话**：P0 现有运行时均未声明追加输入，建议统一排队并明确提示；不修改适配器能力。
4. **团队嵌套/循环引用**：当前成员只能是智能体，模型中没有团队嵌套；校验器保留未来扩展点，P0 以成员/指挥者一致性验证为准。

## 4. 风险与缓解

- 执行器抽取影响单智能体路径 → 先抽执行器并以现有 22 个测试和 E2E 回归，保持 `RunService` 公共 API 不变。
- 并发状态竞态 → 每个会话串行状态转换、数据库事务、回合事件作为事实来源。
- 无限互 @ → 跳数/轮次/重复抑制/A-B-A/token 预算多层保护。
- 上下文膨胀 → 确定性结构化压缩并保留任务与产出物。
- 运行时能力差异 → 插话降级为排队并在界面显示原因。
- 收敛质量不稳定 → 内置指挥者协议要求结构化字段，收敛产出物单独保存。

## 5. 不在本候选中的内容

团队快照、模式二动态指令、`@全体`、自然语言并行声明、Skill/MCP 实际注入、团队嵌套、安装包与国际化。
